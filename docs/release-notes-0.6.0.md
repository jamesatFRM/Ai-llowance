# Ai-llowance 0.6.0 — Clear limits. Easy connections.

Build 245 improves account setup, reading clarity, recovery and the native Mac dashboard.

- **Simpler setup.** Choose a subscription, then follow one clear sign-in action. Claude and Codex keep separate sign-ins for each email. API credits and spending are in their own section, with required key fields visible and account naming optional.
- **Clear connection progress.** See when sign-in is waiting, usage is being checked, refresh is paused, or the connection needs another try. Setup reports Connected after a fresh report is available. Retry a failed API key on the same account, continue a pending Codex sign-in in the browser, and correct an xAI team ID without adding a duplicate account.
- **Clear weekly and 5-hour readings.** Shared reading labels distinguish the weekly allowance, a reported 5-hour window and API dollars. Weekly-only plans are supported; missing information stays unavailable and saved readings retain their original observation time.
- **A more refined dashboard.** Account cards fit the available width, recovery actions point to the next useful step, and charts do less work while the dashboard is hidden. No new background polling or timers were added.
- **Durable, understandable history.** Daily consumption summaries retain 366 days, separate measured zero from missing coverage, and preserve an unreadable history file as a private recovery copy before replacement. Updates keep the existing account storage and history location.
- **Private support diagnostics.** Review a local, redacted report in Settings → Advanced before copying it. Names, emails, keys, paths and usage amounts are excluded. Nothing is submitted automatically.
- **Native Mac controls.** File and Window menus support standard settings, close and minimize shortcuts.

Signed and notarized for Apple silicon and Intel Macs on macOS 14 or later. Install from Ai-llowance → Settings → Updates → Check for Updates.

The release artwork uses illustrative UI, not an actual app screenshot. Provider sign-in and available limits still depend on the provider and its installed CLI.
